# ORE — Open Roleplay Engine

**Русский** | [English](README.en.md)

**Скачать для Windows x64.** Файл `ORE-launcher.bat` доступен на странице [Releases](https://github.com/olegpro171/Open-Roleplay-Engine/releases).

ORE — приложение для общения с ИИ, заточенное для длительных ролевых игр или написания историй. В центре внимания — долговременная память, простота настройки и детальный контроль над промптами. Приложение открывается в браузере. При желании к нему можно подключиться с телефона в той же локальной сети.

## Быстрый старт

Для начала вам потребуется компьютер и доступ к OpenAI-совместимому API Chat Completions.

### Варианты подключения к API

- [Z.ai API](https://docs.z.ai/guides/overview/quick-start) — доступ к моделям GLM с оплатой по мере использования.
- [GLM Coding Plan](https://z.ai/subscribe) — Проверено, что подписка работает с ORE. Z.ai указывает SillyTavern (приложение аналогичное ORE), среди поддерживаемых приложений. [Список приложений](https://docs.z.ai/devpack/tool/others#supported-tools), [условия подписки](https://docs.z.ai/legal-agreement/subscription-terms#4-usage-rules).
- [NanoGPT](https://nano-gpt.com/models/text?scope=subscription) — подписка даёт доступ к большому числу моделей ИИ с открытыми весами, включая GLM и DeepSeek.
- [OpenRouter](https://openrouter.ai/pricing) — доступ к большому числу моделей, в том числе закрытых (GPT, Claude, Gemini и др.). Для платных моделей действует оплата по мере использования.
- **Локальные модели.** Если у вас мощный ПК и вы не хотите платить за API, некоторые модели ИИ можно развернуть локально. Например, [LM Studio](https://lmstudio.ai/docs/developer/openai-compat) позволяет запустить локальный API-сервер.

Узнайте базовый URL API вашего сервиса и получите API-ключ, если он требуется.

Далее установите **Open Roleplay Engine**.

- **Windows x64.** Скачайте `ORE-launcher.bat` со страницы [Releases](https://github.com/olegpro171/Open-Roleplay-Engine/releases) и запустите его. Нажмите **Enter** на пункте **Запустить ORE**.
- **Linux/macOS.** Соберите программу из исходного кода вручную или с помощью скрипта `./start-dev.sh`. См. [руководство по запуску из исходного кода](docs/RELEASES.md#working-tree-development).

После запуска ORE откройте указанный адрес и задайте пароль владельца. Этот пароль потребуется для доступа к приложению с других устройств через локальную сеть.

Если нужный язык не выбран автоматически, откройте **Settings → Language → Interface language**.

На странице **Новый чат** нажмите **Создать** в блоке **Подключение**.

1. Укажите **Базовый URL API** вашего сервиса, например `https://openrouter.ai/api/v1` или `https://api.z.ai/api/paas/v4`, и введите **API-ключ**, если он требуется.
2. Откройте меню **Идентификатор модели** и выберите модель для этого подключения или введите её идентификатор вручную.
3. Кнопка **Отправить тестовое сообщение** проверяет, отвечает ли выбранная модель. Если проверка прошла успешно, сохраните подключение.

На этом техническая часть настройки приложения завершена.

Далее создайте или импортируйте персонажа. В блоке **Персонаж** нажмите **Создать**, заполните имя и описание и сохраните персонажа. Добавьте приветствие, если хотите, чтобы персонаж начал разговор. Если у вас уже есть карточка, выберите **Персонажи → Импортировать персонажа**. ORE читает карточки V1/V2/V3 из JSON и PNG.

Выберите персонажа и, по желанию, персону — описание того, за кого играете вы. Нажмите **Начать чат**.

Чтобы создать ещё один чат, выберите **Библиотека → Чаты → Новый чат**. В разделе **Библиотека → Чаты** также можно импортировать чат из другой программы в формате JSONL, совместимом с SillyTavern.

## От автора

Зачем ещё одно приложение для общения с ИИ? Мне хотелось простое приложение со встроенной долговременной памятью, которое легко настроить. Я не нашёл проекта, который бы закрывал эти потребности без компромиссов, поэтому создал свой. В первую очередь это мой проект для души.

Чтобы осуществить этот проект, я использовал ИИ для разработки, а сценарии использования проверял вручную. У меня высокие требования к качеству и удобству интерфейса, поэтому я многократно проверяю разные сценарии использования и тщательно дорабатываю интерфейс.

Приложение всё ещё в активной разработке, и в нём могут оставаться изъяны. Моя конечная цель — довести текущие возможности до идеала и сохранить простоту приложения. Я буду благодарен за сообщения об ошибках через [GitHub Issues](https://github.com/olegpro171/Open-Roleplay-Engine/issues).

Главный принцип этого проекта — простота. Я предпочитаю добавлять только те функции, которые делают приложение удобнее или улучшают качество ответов ИИ.

## Что здесь есть

- Библиотека персонажей, персон и лорбуков.
- Редактор промптов и предпросмотр собранных сообщений.
- Русский и английский языки интерфейса, разные темы.
- Доступ с телефона по локальной сети и резервное копирование.
- Без сбора аналитики и телеметрии.

## Многоуровневая нарративная память

Чтобы длинная история помещалась в заданный бюджет, ORE объединяет старые ходы в сводки, а недавние передаёт модели дословно. По мере роста истории ORE объединяет группы сводок в более компактные сводки следующего уровня.

Целевой размер входа задаётся для каждого чата. В пресете контекста можно задать минимальное число дословных ходов, размеры групп и промпты для сводок. В разделе **Просмотр памяти** можно прочитать сводку, сверить её с исходными ходами и внести правки.

Возможности системы зависят от способности модели ИИ извлекать факты из текста и сжимать предыдущие сводки, сохраняя значимые факты и отбрасывая лишние детали.

## Установка

Вам нужен компьютер, браузер и доступ к провайдеру модели.

### Лаунчер для Windows

Скрипт установки находится в файле `ORE-launcher.bat`. Загрузите его со страницы [Releases](https://github.com/olegpro171/Open-Roleplay-Engine/releases).

Поместите этот файл в папку, где вы хотите установить ORE, и запустите его двойным щелчком.

ORE запустится через три секунды. Нажмите **Enter**, чтобы запустить сразу, или нажмите стрелку, чтобы остановить отсчёт и выбрать действие. При первом запуске лаунчер скачает и проверит последний выпуск для Windows, установит его в папку `ORE-internal/` и запустит ORE. При следующих запусках ORE подготавливает обновления в фоновом режиме. Когда в консоли появится сообщение о готовности обновления, перезапустите ORE.

В разделе **Настройки лаунчера** выберите, что открыть после запуска ORE. По умолчанию откроется ваш обычный браузер. Для установленного веб-приложения ORE выберите **Открыть ярлык веб-приложения…** и укажите его ярлык Windows (`.lnk`). Если выбрать **Ничего не открывать**, адрес ORE останется в окне лаунчера.

Чтобы остаться на определённой версии, выберите стрелками **Управление версиями**. Выберите установленную сборку или откройте **Список выпусков**, затем подтвердите **Использовать эту версию**. В обоих списках отображаются названия выпусков с GitHub. При открытии экрана лаунчер обновляет названия и сохраняет их для работы без сети. Перед переключением лаунчер проверит совместимость сборки с вашей базой. Фиксированная версия запускается без сети, автоматические обновления приостанавливаются. Чтобы возобновить их, выберите **Последний выпуск · Автообновление**. Для возврата нажмите **Esc**.

Если старый лаунчер не обновляет ORE, скачайте новый лаунчер со страницы [Releases](https://github.com/olegpro171/Open-Roleplay-Engine/releases), остановите приложение, замените `ORE-launcher.bat` рядом с существующей папкой `ORE-internal/` и запустите его двойным щелчком.

Папка `ORE-internal/` содержит данные приложения. Её удаление приведёт к потере сохранённых данных.

В Windows x64 используются встроенные 64-разрядные Windows PowerShell 5.1 и .NET.

### Запуск из исходного кода

Клонируйте репозиторий и запустите из его корневой папки скрипт для своей платформы.

| Платформа | Команда |
| --- | --- |
| Windows x64 | `.\start-dev.bat` (можно также дважды щёлкнуть по файлу) |
| macOS или Linux с glibc | `./start-dev.sh` |

Оба скрипта собирают приложение с учётом ваших локальных изменений в папке `ore-development/`, используя отдельную копию Node.js, а затем запускают ORE. Перед повторной сборкой остановите запущенную версию сочетанием **Ctrl+C**. [Требования для сборки](docs/RELEASES.md#working-tree-development)

Если вы отдельно собрали переносимую версию для macOS или Linux, запустите выбранную сборку командой `./start.command` из папки установки.

## Устранение неполадок

**ORE не запускается после обновления в Windows.** Прочитайте сообщение об ошибке и откройте **Управление версиями**. Выберите сборку с пометкой **Последняя успешно запущенная** или **Предыдущая рабочая версия**. Если вы переместили базу данных, выберите **Открыть чаты из перенесённой или восстановленной базы…** и укажите её новое расположение. Затем выберите **Запустить ORE**. Если сборка не может прочитать базу, см. [руководство по восстановлению](docs/RELEASES.md#database-upgrades-and-explicit-recovery).

Если само меню лаунчера недоступно, остановите ORE и выполните эту команду в PowerShell из папки с файлом `ORE-launcher.bat`.

```powershell
.\ORE-internal\recover-app.bat --list
```

Если в списке есть предыдущая рабочая сборка (`previous working`), выполните `.\ORE-internal\recover-app.bat --previous`. Команда проверит, может ли эта сборка прочитать вашу базу данных. Если проверка прошла успешно, снова запустите `ORE-launcher.bat`. Автоматические обновления будут приостановлены. Чтобы возобновить их, выберите **Последний выпуск · Автообновление** в лаунчере или остановите ORE и выполните `.\ORE-internal\recover-app.bat --resume-updates`.

В macOS и Linux список сборок можно посмотреть командой `./recover.command --list` из папки переносимой установки. [Варианты восстановления](docs/RELEASES.md#database-upgrades-and-explicit-recovery) · [Прежние установки](docs/RELEASES.md#legacy-installations)

## Доступ с телефона

Включите доступ в разделе **Настройки → Телефон / локальная сеть** на компьютере с сервером. Откройте рекомендуемый адрес по имени компьютера на телефоне в той же локальной сети. Если он не работает, попробуйте показанный рядом локальный IPv4-адрес. Он доступен и при ошибке определения имени компьютера. При смене адреса может понадобиться войти снова. IPv4-адрес может измениться — актуальный адрес указан в настройках. Компьютер должен оставаться включённым и не переходить в сон.

## Данные и резервные копии

Приложение хранит содержимое чатов, данные о персонажах, API-ключи и другие данные локально на компьютере, где оно установлено.

По умолчанию установки из лаунчера Windows используют `ORE-internal/data/roleplay.sqlite` и `ORE-internal/.env`. При запуске из исходного кода используются `data/roleplay.sqlite` и `.env` в каталоге репозитория.

Содержимое запросов отправляется на настроенный вами эндпоинт модели. К нему применяются правила конфиденциальности этого сервиса.

## Перенос ORE в другую папку на Windows

ORE можно перенести в другую папку. Чаты, настройки и остальные данные переместятся вместе с папкой `ORE-internal/`.

1. Сохраните резервную копию через **Настройки → Резервное копирование** за пределами папки установки. Нажмите **Ctrl+C** в окне лаунчера и дождитесь остановки ORE.
2. Переместите `ORE-launcher.bat` и папку `ORE-internal/` в локальную папку с правом записи, где ещё нет другой установки ORE. Оставьте файл лаунчера рядом с папкой и сохраните её имя `ORE-internal`.
3. Запустите `ORE-launcher.bat` из новой папки и проверьте, что сохранённые чаты открываются.

## Удаление ORE

1. Чтобы сохранить чаты, память, библиотеки и подключения, создайте резервную копию в разделе **Настройки → Резервное копирование** и сохраните её за пределами папки, которую собираетесь удалить. Если хотите сохранить свои языковые пакеты, скопируйте их отдельно. См. [что входит в резервную копию](docs/DATA.md#content-backups).
2. Нажмите **Ctrl+C** в терминале или окне лаунчера, где запущен ORE, и дождитесь остановки. При закрытии вкладки браузера сервер продолжает работать.
3. **Windows.** Удалите лаунчер `ORE-launcher.bat` и папку `ORE-internal/`. Вместе с ними удалятся все данные приложения. **При запуске из исходного кода** удалите папку репозитория. Чтобы удалить только сборку, созданную `start-dev.bat` или `start-dev.sh`, удалите `ore-development/`.

**Временные файлы.** Если работа лаунчера Windows была прервана, в `%TEMP%` могут остаться папки `ore-types-*`. После остановки ORE эти папки можно удалить вручную.

Черновики, некоторые настройки и файлы cookie сохраняются в браузере на устройстве, с которого вы использовали ORE. Чтобы удалить их, очистите данные сайта для адреса ORE на каждом устройстве.

## Как сообщить об ошибке

- **Сообщить об ошибке.** Откройте страницу [GitHub Issues](https://github.com/olegpro171/Open-Roleplay-Engine/issues) и проверьте, нет ли там похожих сообщений. Если таких нет, нажмите **New issue**. Опишите, в чём состоит проблема и как вы с ней столкнулись. Укажите версию ORE, браузер и операционную систему. Если это поможет воспроизвести проблему, приложите скриншот или запись экрана. Не публикуйте API-ключи и резервные копии ORE.
- **Отправить pull request.** Опечатки, правки перевода и небольшие исправления с понятным ожидаемым поведением можно сразу отправлять в pull request. Новые функции и изменения поведения промптов, памяти или работы с сохранёнными данными сначала обсудите с автором проекта в [GitHub Issues](https://github.com/olegpro171/Open-Roleplay-Engine/issues). Сделайте форк, создайте рабочую ветку от актуальной `develop` и выберите `develop` основного репозитория как целевую ветку. Опишите, зачем нужно изменение, как его проверить и какие проверки вы выполнили. Если есть связанная задача, укажите её. Для изменений интерфейса приложите скриншоты, а для изменений памяти или хранения данных — результаты регрессионных проверок.

Автор проекта объединяет принятые изменения в `develop`, проверяет кандидата на выпуск в `staging` и переносит проверенный коммит в `main`. Подробнее в [руководстве по выпуску](docs/RELEASES.md#automated-windows-releases).

## Разработка

Перед изменениями приложения прочитайте [AGENTS.md](AGENTS.md), [контракт продукта](CONCEPTS.md) и [руководство по архитектуре и разработке](IMPLEMENTATION.md). Эти документы ссылаются на подробные контракты подсистем.

Для разработки из исходного кода используйте Node 24 или Node 22.14+ в пределах основной версии 22.

```sh
npm run build     # Проверка типов и сборка
npm test          # Тесты ядра, сервера и хранилища
npm run test:e2e  # Браузерные сценарии. Сначала выполните сборку
npm run check     # Сборка и оба набора тестов
```

Для браузерных тестов нужны `npx playwright install chromium webkit` и разрешение запускать локальные серверы. WebKit используется для проверки сохранения прокрутки при выборе записей лорбука в движке Safari. Тесты используют временные данные и имитацию провайдеров.
