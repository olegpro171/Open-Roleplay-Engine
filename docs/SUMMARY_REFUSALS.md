# Saved summary refusal recovery

Accepted and implemented for local testing on 2026-10-24. This extends [context editing](CONTEXT_EDITING.md), rather than changing original transcript content or the ordinary summary-output gate.

Saved refusal checks use an explicit detector version, independent of the app release. Increase `summaryRefusalFilterVersion` when saved-text detection changes. Context reads, including Story, cache a result for each saved summary revision whose check is missing or from a different detector version. Repeated reads reuse that result. Checks inspect text locally and never call a model. They add only quality metadata; source/text revisions, selected coverage, turns and historical requests stay unchanged. Historical versions are checked for safe future repair comparisons, but only current approved identities appear as findings.

Story shows a finding count and opens Memory. Selected memory whose actual child, earlier-context or editorial dependency contains an unresolved refusal cannot be used for roleplay or ordinary preparation. This is enforced on the server, including submissions and response regeneration, rather than just by disabling Send. Unrelated retained alternatives do not block roleplay but are excluded from saved-summary reuse. Summary-off request assembly continues to ignore saved memory.

## Review actions

**Keep as is** records the user's judgment that the exact saved revision is a false positive for this filter version. It changes no narrative text, selection or source provenance. It permits that text to be used again. A changed summary or another detector version needs a new check; closing Memory records no acceptance. Previously recorded source staleness is not cleared by keeping a finding.

**Regenerate & repair** marks the saved revision as requiring reconstruction. It retains all versions and invalidates dependent memory through ordinary dependency traversal. Explicitly requested inactive roots also enter repair; unrelated stale saved alternatives remain outside its scope. Open **Repair summaries** to make model requests. The unusable summary is rebuilt from all current source turns at level 1, or clean current children at higher levels, using the extraction/promotion prompt. Original earlier-memory dependencies and current clean editorial inputs are supplied. Required sources are not truncated to fit; an oversized request fails before a model call. Reconstruction cannot use the no-call unchanged-input shortcut, and its candidate requires approval before consumers are repaired.

A clean consumer still uses minimal repair, with the replacement source and a neutral `beforeOmitted: 'unusable_summary'` marker in place of the previous refused text. A withheld previous input is not a known unchanged baseline: neither local revalidation nor identical-output auto-approval applies. Other known unchanged inputs retain the existing minimal-repair shortcuts. Model-bound summary fields are assembled anew; historical provider bodies are never replayed. Detected refusals are excluded from previous-summary text, previous changed summary inputs, earlier context and editorial inputs. An unresolved current source fails clearly so it can be resolved first. Original transcript content and editable model instructions are not censored by this summary-only policy.

**Delete from here onward…** previews a chronological suffix from the earliest covered turn among the chosen findings. It includes every saved identity with any version crossing that point, across all layers, plus the ordinary all-version dependency cascade. A parent spanning turns before the chosen boundary is therefore removed too; the preview counts archived turns actually returning to verbatim, which can start earlier. The preview lists affected identities and warns about manual corrections. Cancel changes nothing. Confirm removes all affected versions atomically and retains only the surviving selected prefix. Original turns and historical request bodies survive, and deleted preparation results remain labeled. **Prepare chat** subsequently rebuilds/reuses memory under normal rules, without repair review for newly generated summaries.

## Durability and concurrency

Quality metadata and the reconstruction reason extend existing summary JSON; no SQL schema migration or rewriting of historical request bodies is needed. Backup validation includes these optional fields, preserving decisions and outstanding reconstruction across export/import. Existing data without the fields remains valid and is checked on read.

Resolution commands check the chat revision, current approved summary revisions, filter version, and operation ownership inside a transaction. Running generation/preparation and pending repair review block conflicting actions. Deletion and its preparation-result/selection bookkeeping commit together; failure preserves the previous committed state. Stale previews must be reopened. Repeated stale commands cannot delete or mutate newer state.

Repair retains existing reviewed lifecycle rules: approval saves before dependent generation; Close cancels current work and discards unapproved candidates/local edits; approved progress and unresolved reconstruction reasons survive. Late cancelled results cannot commit. Reopening resumes from committed work with fresh model requests; restart never automatically retries a paid request. Preparation retry controls do not apply to reviewed repair.

## Verification limits

Temporary SQLite/coordinator tests cover legacy detection, revision-safe decisions, historical request preservation, forced reconstruction with unchanged sources, exclusion of refused baselines, consumer repair, rollback, cancellation and restart. Browser tests exercise discovery, false-positive acceptance, repair approval, and deletion/repreparation at desktop and phone-sized widths against the local mock provider. These checks establish structural behavior and request contents; they do not establish real-model quality, complete refusal detection, or actual phone behavior. A clean-looking consumer can still have lost facts through an earlier refusal, so checking its text alone does not replace dependency repair.
