# Chat formatting

Story uses one Markdown renderer for greetings, user input, assistant responses, selected response versions and streamed/failed/cancelled partial text. Emphasis, strong emphasis, headings, ordered/unordered lists, blockquotes, inline/fenced code and the GitHub-flavored table, strikethrough and task-list extensions are supported. Soft line breaks remain visible. Code and tables scroll horizontally inside the conversation when needed.

Editors and persistence keep the original source. Speech/prose styling is a display transformation; Markdown images additionally have the model-input exclusion described below. Lore scanning retains the original transcript, and saved historical requests stay immutable. Existing records need no migration. Raw HTML is displayed literally and never executed. Links accept HTTP(S), mailto and same-page fragments, with external destinations opening in a separate tab without opener/referrer access. Relative and unsafe schemes are inert. Markdown images with absolute HTTP(S) destinations load inline, including empty-alt and reference-style images. They load lazily, fit the message width without changing aspect ratio, and send no referrer. Blocked schemes, relative URLs and failed loads display `[Image: alt text]` (or the localized generic image label). Raw HTML images remain literal text. Remote resources load directly in the browser; no server proxy or saved image copy is introduced. Their continued availability and browser mixed-content restrictions still apply. Turn-size observation keeps the latest reply in view when an image finishes loading, while retaining an earlier reading position.

## Images and model input

Before assembling future model requests, the shared core parser removes rendered Markdown images, their alt text and destinations. Image-only links and definitions used only by images are also removed; definitions shared with ordinary text links stay available to those links. Escaped syntax, code examples and raw HTML remain literal prose. Surrounding source Markdown is preserved without serialization. Editors, stored greetings, alternate replies, exports and backups retain the original image syntax. An image-only part contributes no outgoing message, but its turn retains its identity, completion, coverage and compaction membership.

The same filtering applies to resolved prompt/card/persona/lore text and memory, and to summary extraction, promotion, earlier context and repair before JSON encoding. Token budgets measure the filtered outgoing input. First-layer requests retain original source baselines as local provenance outside the provider body, so repairs still compare the actual saved source revisions. Saved summaries and historical requests are never rewritten; legacy summaries can still contain prose previously derived from images. Image edits retain ordinary source-revision/staleness rules.

## Quoted speech

Balanced `"…"`, `“…”`, `«…»` and `„…“` spans are bold and use the selected speech color, including the quotation marks. Nested pairs are included in the outer span. Straight and curly single quotes never start or end a quotation, including leading apostrophes such as `'em`. This recognizes quoted text, including quotations that are not literally spoken dialogue; it does not infer narrative meaning. Unclosed streamed quotations remain ordinary text until their closing mark arrives.

Speech styling covers complete detected spans, including em dashes (`—`) inside quotations and opening/resuming dialogue dashes. Dashes separating speech from recognized author clauses remain plain because they fall outside those spans.

Detection runs on inline prose after Markdown parsing. A quotation may cross emphasis, strong emphasis or link-label boundaries. Code, images, raw HTML and other non-prose nodes form barriers; code contents and link destinations are never restyled. Parsing is local to an inline block, so a quotation does not extend across blank paragraphs, table cells or unrelated list items.

## Optional Russian dialogue

`russian-dialogue.ts` is independent of the quotation detector. Its deliberately limited heuristic:

1. Requires an em dash followed by horizontal whitespace at the start of a line, allowing indentation and nonbreaking spaces. An em dash inside ordinary narration does not activate dialogue mode.
2. Uses the opening dash to identify speech. Spaced em dashes inside balanced quotations do not divide its detected coverage; the opening dash and internal dashes receive speech styling.
3. Checks at most twelve words of the first clause after a separating dash, stopping at sentence punctuation, a colon or a quotation. An explicit vocabulary recognizes common attribution/action verbs, including inflected `передразнила`, `буркнула`, `пробормотали` and present-tense `отвечает`. A later sentence or quoted phrase cannot supply an attribution for an earlier spoken aside.
4. After a speech punctuation boundary, also recognizes third-person action/body-language clauses with a past-tense predicate: `она отшатнулась`, `у Аири голос сорвался`, `Щёки у неё горели`, or `её голос дрожал`. This fallback requires an initial third-person pronoun or body/voice subject (including an owner introduced by `у`). First/second-person subject cues such as `у меня` or `руки у тебя` prevent the fallback from consuming the speaker's own aside. The separating dash and the entire author clause, including subsequent narrative sentences, stay plain.
5. Resumes speech at a following spaced em dash when the author clause ends with a comma, colon or sentence punctuation. The resuming dash receives speech styling. Other speech punctuation remains styled; whitespace before an author separator stays plain.
6. Resets at each line. A line containing code or another non-prose barrier is left to quotation-only detection.

Exact-span tests cover the original six examples and the five follow-up examples; rendered-prose and browser tests also exercise every follow-up case. In particular, `представляешь?` stays within speech, nested quoted replies do not become author clauses, and `он на секунду замолчал…` is excluded before speech resumes. The follow-up cases exposed the original short verb list's inability to recognize additional attributions or body-language narration; the expanded vocabulary and structural fallback address those patterns. This is not a Russian grammar parser: unfamiliar attribution verbs, unusual punctuation and narrative text resembling an attribution can still produce missed or incorrect boundaries. Body-language clauses without a recognizable past-tense predicate or subject cue are not inferred. Line-wrapped em-dash dialogue is not inferred across separate lines. No model calls or language service are used.

Set `defaultSpeechOptions.russianDialogue` to `false` in `src/web/ChatMarkdown.tsx` to disable this detector while retaining quotes. The component also accepts independent `speech` options for tests/future controls. The combiner in `direct-speech.ts` is the only integration point for removing the Russian module. Each Character and Persona editor has a **Speech color** selector. Story uses the selected character’s color for assistant speech and the selected persona’s color for user speech, including greetings, response versions and streamed/terminal partial text. Cards start at **Not set**. **Set color** enables an override; **Clear color** removes it when the card is saved. Unset cards and missing selections use the matching default from **Application Settings → Chat appearance**, initially light blue (`#a8c9f0`). Explicit card colors take precedence over app defaults. Changing a saved color updates existing chat presentation. The renderer sets `--direct-speech-color` separately on each Markdown container; detection remains unchanged.

Colors are optional local library metadata (`speechColor`, opaque six-digit hex; null in a save command clears the saved value), stored in the existing JSON records without a migration or rewrite of older data. Omitted values preserve saved colors in older-client/internal updates. Color-only saves advance the library cache revision while preserving prompt-bearing record revisions, chat revisions, memory, lore and historical requests. Colors never enter prompt sources or compatible character/persona exports. Duplication and application backups retain them. Unsaved colors follow the ordinary editor close, failed-save and conflict handling. Application defaults are saved together with a revision check in a private `<database>.appearance.json` sidecar. They update other open windows through existing change notifications, survive restarts and content import/wipe, and are excluded from content backups. Failed writes preserve the prior configuration; malformed files report an error instead of silently resetting defaults. If loading appearance fails, Story remains available with a visible error and Retry, using the last successfully loaded appearance or factory defaults on first load. The appearance editor saves valid changes immediately, retains failed choices with Retry, and automatically reconciles competing revisions without overwriting unrelated fields. App-default color pickers save on valid hex, HSL or palette changes and close without undo; library pickers keep Apply/Cancel.

## Chat text size

**Application Settings → Chat appearance → Text scale** provides a keyboard-accessible slider with ticks at 90%, 100% (default), 110% and 120%. The example beneath it uses the same Markdown renderer and prose line height as Story, updating immediately from the unsaved draft. Each slider change saves automatically through the shared revision-checked settings queue. Existing messages, greetings, selected response versions and live/terminal partial replies use the saved size; controls, the composer and source editors retain their existing size. The ordinary message base remains 15px at 100%, with proportional Markdown headings, code and tables. Narrow screens wrap the example naturally.

The scale is server-wide and uses the same revision, failure recovery and backup boundaries as default colors. Appearance sidecar version 2 stores it. Existing version-1 files load at 100% while preserving their colors and revision, and upgrade on the next successful atomic save. Older clients saving only colors preserve the committed scale. No transcript or model input changes.

## Verification

`tests/direct-speech.test.ts` checks exact ranges, all supplied examples, related action/voice patterns, negative spoken asides, quote variants, apostrophes, nonbreaking spaces, ordinary narration and independent disabling. `tests/chat-markdown.test.ts` checks rendered Markdown, the follow-up author clauses, cross-format spans, code barriers, incremental incomplete text, inert HTML/unsafe URLs, safe inline images and empty-alt/reference images. `tests/inline-images.test.ts` checks image exclusion, literal code, references, image-only coverage, exact budgets, extraction, promotion, prior context, repair and preserved source baselines. `tests/browser/markdown.spec.ts` exercises copied greetings, source editing, version selection through every follow-up case, reload, inline image loading/failure and mock-provider streaming images, exact filtered saved/actual mock-provider requests, and desktop/phone-sized image bounds, with screenshots and overflow checks. `tests/speech-color.test.ts` checks legacy records, restart, duplication, stale saves, strict color validation, clearing and prompt/export exclusion. `tests/appearance.test.ts` checks authenticated default saves, restart, conflicts, input validation, write rollback, malformed configuration, temporary-file cleanup, allowed scales and version-1 compatibility. `tests/browser/speech-color.spec.ts` checks both selectors, failed-save draft recovery, updates to existing chat presentation, app-default precedence, cleared overrides, keyboard selection of every text scale, matching preview/message sizes, unchanged control size, failed-save scale retention, reload and cross-window refresh/conflict handling at desktop and phone-sized widths. The Markdown browser workflow also asserts distinct character/persona colors through mock streaming. These checks establish the documented patterns, not universal grammatical accuracy or actual phone behavior.
