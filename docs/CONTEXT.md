# Memory, budgeting and repair contract

This is the current agent reference for managed coverage, preparation, corrections, repair and reference counting. [CONCEPTS.md](../CONCEPTS.md) owns turn/prompt semantics and [IMPLEMENTATION.md](../IMPLEMENTATION.md) owns module/operation boundaries. These rules apply with Summary enabled; Summary-off uses request-local recent whole turns and makes no memory calls.

## Measurement and limits

`src/core/tokens.ts` uses local `o200k_base` for every model, with no model mappings, service, byte fallback, character divisor or provider-derived calibration. Encode each resolved message's actual text (special-looking strings as ordinary text), not its JSON escapes. Framing is 3 units plus 3 per message plus encoded role strings. This is a shared approximation, not an endpoint template guarantee. The bounded cache holds 512 entries and at most two million UTF-16 units, excluding individual texts over 100,000 units.

Use this counter for full input, allocations, summary labels/separators, promotion pressure, complete-request savings and summarizer source/prior-context windows. Model-text filtering precedes counting. Summary output size is a soft prompt target; measure actual output. Reserve summarizer output using its Connection limits.

Separate the input-only working target from physical context/input capacity and reserved output. Do not subtract output twice. Sending fits at target equality; the optional overshoot allowance permits only an excess strictly less than its threshold (default enabled, 100 tokens). Equality at the threshold prepares. Preparation and post-response checks aim for the target, not target plus allowance. Physical overflow fails independently and does not trigger preparation by itself. Required content cannot be silently truncated or guarantees reduced.

New saved request metadata records counting method/version, reference encoding, approximate framing, limits and `verified: false`. Keep old bodies, estimates and usage immutable, including historical model/fallback metadata. Endpoint usage stays attached to its exact attempt and may be unavailable. Changing estimates or settings alone leaves the saved selection in place. Normal UI retains estimate wording; detailed technical metadata belongs in inspection, not repeated labels.

Previews/plans use authoritative full server assembly. Estimate-only projections contain no prose; full inspection loads on demand. Pending input, fixed blocks, eligible lore, notes, pinned excerpts, summaries and framing all count. Read-only inspection may show overflow/staleness without bypassing generation checks.

The pinned block is fixed roleplay input. Reserve it before selecting the Summary-off suffix and charge any overlapping Messages copy as ordinary history. Managed planning measures the full branch for pins even while testing a reduced verbatim tail. A compacted turn can leave Messages while its pin still consumes space. Required-input overflow can be resolved in Pinned turns. Pin changes make no provider calls and keep the committed memory selection.

## Stable coverage and preparation

Persist the committed selection/cutoff separately from saved summary existence. Emit selected coverage in original conversation order, without overlapping parent/child/original representations or unexplained gaps. Restart loads that state; never rebuild it from transcript length or current token totals.

Protect the newest `L` completed turns and all pending input. Intentionally blank completed turns count. Summarize exactly the oldest `B` eligible completed verbatim turns when a full batch remains outside the minimum tail. For `L=100`, `B=3`, 102 verbatim completed turns provide no full batch. The residual stays verbatim. A raised minimum can restore whole batches to verbatim during Prepare. If it prevents inclusion of an approved correction, use reviewed repair or deletion. Summary-only prompts preserve their archived cutoff and can promote within it.

When no first-layer batch is eligible and input still overflows, promote only full contiguous oldest groups of selected summaries. Preserve the configured newest retained count per source level (zero allows no floor). Older selected spans must be at least as compact as newer spans; a promotion cannot make its range deeper than an older selected span.

For positive summary pool `S` after required non-summary input and actual tail, level `k` has soft allowance `A_k=S/2^k`. Rank eligible levels by selected token occupancy `U_k/A_k`, breaking ties toward the deeper level. `U_k` excludes inactive saved children. Take that level's oldest eligible group. Soft shares neither reserve/pad space nor trigger work on their own. Nonpositive capacity or no eligible candidate fails when required history cannot fit. Actual tokens, not summary count, determine pressure.

Capture source, dependency, configuration, selection and operation revisions. Save each paid attempt and its request before dispatching outside the transaction. Validate output and complete-request savings, then recheck those revisions and save the approved result with its working coverage. A non-shrinking output stops preparation. Commit the selection and cutoff with each generated result that preserves valid coverage, freshness and approved corrections. A result that still needs a later correction stays saved for reuse until the replay can represent that correction. A valid selection may be over target. Recheck complete input against the limit at the first valid fit. Failure and cancellation retain the latest committed selection and any completed results. Save next summary advances the current selection by one eligible replacement and saves that replacement and its selection together.

Extraction and compression have separate editable conservative continuity prompts. Each batch is standalone; promotion rewrites the whole group rather than concatenating deltas. Supply at most three fitting preceding selected summaries as interpretive reference, tracking their revisions as dependencies but not extra coverage. Keep live lore, Author’s notes and the dedicated pinned block out of narrative summarization. Facts, chronology, uncertainty and knowledge attribution are semantic goals, not validated guarantees.

Manual Prepare, Send, Regenerate and post-reply work share the same next-operation policy. Start with all original turns and an empty working cutoff. Regenerate uses its request-local view of those turns, with the old reply excluded, and saves the fitting selection for that request. Summary-only prompts replay promotions within their saved coverage. Stop at the first valid fit, which may return detail to verbatim or keep finer memory than the previous selection. Manual Prepare operates without sending a message. Send and Regenerate use the sending allowance to decide whether to start preparation. A successful response commits before its follow-up job, which measures saved input against the target without any next draft. Opening a chat, changing sources or settings, selecting variants and typing drafts make no provider calls.

## Exact saved reuse

Reuse fresh approved Level 1 summaries at compatible whole boundaries in the saved layout, including batches created under earlier sizes. Use the current size for new batches. Reuse a parent only for the exact eligible ordered child revisions, subject to chronology and retention floors. Recheck prior and editorial dependencies and complete-input savings. Required correction coverage can be selected even if it increases the estimate. Resolve the summarization Connection only for a model call. A null summarization Connection selects the roleplay Connection. Importing a context preset whose saved Connection ID is unavailable uses this default and shows a warning. A matching local ID is preserved.

Replay uses indexed saved results along one chronological path. It does not search competing tilings or record a duplicate step per reused result. Commit consecutive reused results together at the next wait or at the final fit if their selection is valid. Save next summary still records its single reuse and selection. Paid steps record before and after working estimates and keep their original requests. A saved replay that reaches the same selection without waiting leaves the selection revision and saved results intact. Historical Refresh records and frames remain inspectable with their original turn membership.

Before a replacement that supersedes an unused saved alternative at the same level, pause and show the same dependency-cascade preview as Delete summary. Keep the provenance required by the committed and working selections. If an unresolved correction blocks preparation and there is no eligible repair, offer the same reviewed deletion of that correction and its dependents. Review is required for generated and manually corrected summaries alike. Highlight the deleted summaries and restored turns. Confirm commits the reviewed deletion and any cutoff changes before replanning. A later preparation failure leaves the confirmed deletion committed. Decline cancels the run, retaining memory at the pause. A pending Send turn and the selected Regenerate reply are preserved on decline. Restart interrupts an unanswered review and an explicit retry creates a fresh review. Mark removed preparation results in history and retain their original requests.

## Layout changes

Changing Turn batch or Promotion group preserves the committed layout, its historical versions, and the children and dependencies needed for provenance. Keep saved checkpoints that still match full batches after the cutoff or full promotion groups in the committed selection. Prune superseded inactive layouts, including promotions wholly inside the archived prefix. For example, a committed cutoff at turn 12 stays in place when the batch grows from three to four. An unused 13–15 summary is discarded and the next eligible batch is 13–16. Switching back can require generating those summaries again.

Review the affected branches and any approved correction that would be removed before committing a size change or latest-turn deletion. A shared preset can affect every branch of multiple chats. The setting or deletion, cleanup and selection checkpoint commit together with current revisions and idle guards. Reads, restarts and upgrades preserve saved memory and make zero model calls. Legacy stored alternatives remain subject to exact next-operation eligibility.

## Manual correction authority

Protect the latest approved manual revision of each identity with surviving coverage, including retained alternatives outside the selected tree. Historical versions are inspection, not extra obligations. Empty tombstones/identities without surviving coverage have no inclusion obligation. Do not infer old manual flags away from text equality.

Every selected replacement touching a correction must carry its exact current revision through coverage children or explicitly reviewed `corrections` references. `prior` governs freshness. Alternative identities or original sources do not implicitly contain an editorial addition. Planning, reuse, request assembly and commit validation share this rule.

Stale retained corrections and required current dependencies enter repair. Reconcile against a selected covering summary when possible, otherwise a compatible saved container. Repair of an inactive container preserves the committed coverage. Supply all overlapping corrected identities and text with source changes. New editorial membership requires review even when model text is identical. Replay uses fresh saved coverage that carries a required correction. A directly edited parent can anchor the replay where its children lack the edit. Once a promotion carries the exact correction through children or a reviewed link, send only the promoted parent. A correction that cannot be represented in valid chronological coverage blocks the replay for repair or deletion review.

Direct saves compare trimmed storage text after revision/idle/latest-approved checks. Identical saves do not write a version, set manual flags, invalidate dependents, change selection or advance revisions. Changed saves preserve old versions and source links; editing stale memory leaves it stale and supplies the edited baseline for repair. Editing a retained summary does not claim activation in model input.

## Freshness and response variants

Track actual consumed turn parts, child summaries, original earlier-context and editorial revisions. A source edit invalidates every direct consumer and its dependents, including higher layers and summaries outside nominal coverage. Clearing an archived part retains turn membership but removes its prior content; deleting a whole turn changes structure. Never use displayed turn numbers as identities or silently restore edited originals alongside stale summaries.

Concurrency revisions advance monotonically; source-content provenance can return to an unchanged saved response A after A→B→A. That restores freshness only if all other sources/dependencies still match. A repair against B establishes a new baseline; selecting A cannot clear unrelated changes. Regeneration uses the temporary selection described in IMPLEMENTATION; it never rewrites later transcript turns.

## Reviewed repair

Repair explicitly visits current required child/prior/editorial dependencies and retained corrections bottom-up, not every stale historical version. Selected stale memory blocks roleplay; unused stale alternatives do not by themselves. Use a separate editable minimal-repair prompt with the existing summary and complete before/after pairs for all changed consumed inputs. Retain original earlier-context membership; do not select additional prior memory. Changed input must fit together or fail before transport. Persist complete local original first-layer baselines outside provider bodies for subsequent repairs; unknown historical baselines remain unknown.

Changed text, changed coverage/membership, missing baselines and new correction inputs require review. Candidates are editable. Approve & Next saves before generating the next dependent; Approve & Finish completes. Regenerate retains a still-valid candidate if the replacement request fails, but never makes an obsolete candidate approvable. Close cancels work and discards unapproved candidate/local edits, keeping approved progress. Reopen generates fresh remaining work; no draft persistence or automatic paid repair retries.

Within explicit repair only, complete identical consumed text/structure permits transactional local revalidation as a new approved version, preserving flags/old versions/provenance. Exactly identical model output may auto-save only with known baseline and unchanged ordered coverage/dependencies. Record `inputs_unchanged` separately from `model_unchanged`. Every direct consumer of changed A must still be checked even when B returned unchanged. Propagation stops through B only where a dependent's other consumed inputs are also unchanged. Never clear downstream staleness indiscriminately.

Reviews expose old/new prose and the actual incorporated before/after source/prior inputs. Matching/highlighting is textual, not semantic. Rejected heuristic output can be inspected read-only but cannot be approved. Stream phases reflect observed Connecting/Reasoning/Generating activity, not inferred encrypted provider state. Saved failed output is distinct from discardable candidates.

Repair does not rewrite later transcript contradictions. A higher-layer repair cannot recover facts already lost from its sources. Conflicting manual canon and source edits remain a review problem; no semantic authority or automatic continuity rewrite is implied.

## Refusal checks and retries

The summary-output gate rejects obvious refusals/filter metadata, empty/non-text/placeholder output, repetition loops and incomplete/truncated streams. It is heuristic, not factual validation. Late cancelled results cannot commit.

Saved checks use `summaryRefusalFilterVersion`, independent of release identity. Increment it when saved-text detection changes. Locally cache each saved revision/filter result, including historical versions used for future comparisons. Checks change quality metadata only, not source/text revisions or selections, and make no model calls. Current approved identities form findings. Unresolved refused inputs in selected dependencies block use/preparation on the server; unrelated retained alternatives are excluded from reuse. Summary-off ignores them.

- Keep as is records acceptance for the exact text revision/filter only; it clears neither source staleness nor later findings after edits/filter changes.
- Regenerate & repair retains versions, invalidates consumers and explicitly includes requested inactive roots. Reconstruct unusable roots from all clean current turns/children with extraction/compression prompts, original prior dependencies and current clean editorial inputs. Always review these candidates; no unchanged-input shortcut applies.
- Consumer minimal repair supplies corrected sources while withholding refused baselines with neutral `beforeOmitted: unusable_summary` provenance. Withheld inputs cannot qualify for known-unchanged shortcuts. Exclude refused summary text from previous/current summary fields, earlier context and corrections; unresolved current inputs fail. Original transcript/model instructions are not censored.
- Delete from here onward previews all identities with any version crossing the earliest covered finding plus dependency cascade, including crossing parents. Confirm atomically deletes those versions and keeps only a surviving selected prefix; original turns/requests remain. Cancel changes nothing. Subsequent Prepare is ordinary rebuilding.

Quality/reconstruction metadata uses optional summary JSON preserved by backup validation. Resolution commands recheck current approved revisions, filter version, chat and ownership transactionally. Stale previews must reopen. Restart retains decisions/reconstruction reasons without model calls.

Preparation captures the retry policy per job. A run allows up to 100 paid attempts, including failed attempts and retries. Traversing already saved coverage does not consume that allowance. Automatic retry defaults to ten retries per request. A saved maximum of zero uses that default, and the run limit still applies. Only transport and output failures retry, after one cancellable second. Planning, stale state, persistence and non-shrinking failures stop. Check whether the request fits after the last allowed step before reporting the run limit. Reviewed repair has its own explicit actions. Absent retry fields preserve no-retry command semantics.

Story projects the working estimate, target and current step independently of the visible turns. The working estimate can initially rise when replay returns to original turns. It is labeled separately from committed input. A Regenerate job measures its working request with the old reply excluded. Once accepted, Stop aborts provider waits or retry delays, prevents further dispatch and rejects late results. Completed summaries remain saved for reuse. A cancelled Send leaves its turn pending and a cancelled Regenerate retains the previous selected reply. Browser disconnection leaves server work running. Restart marks unfinished work interrupted and requires an explicit action to retry.

## Deletion and verification boundaries

Delete summary previews a reverse dependency cascade across every version, including child, prior, correction and based-on consumers. Keep the selected prefix before the earliest deleted active span and return its archived suffix to verbatim. Retained later summaries qualify for reuse only on an exact eligible step.

Whole-turn deletion at the end of a branch keeps the longest valid prefix of whole committed summaries that leaves the protected completed tail. If deleting turn 15 cuts through a summary for 13–15, surviving turns 13–14 return to verbatim. Shortening the verbatim tail can move the cutoff back further. If the shortened tail still meets the minimum, keep the valid selection. Remove summary identities that cover the deleted turn, and remove previously selected summaries and their provenance where they extend beyond a retreating cutoff. Cascade both removals across all saved versions. Preserve independent inactive summaries even if their source turns are verbatim; they remain available for exact reuse. Preserve history for surviving turns under the ordinary deletion rules, including immutable request bodies and historical deleted-result markers. Earlier-turn deletion continues to use reviewed repair for affected archived coverage.

Clear memory explicitly deletes all summary versions, candidates and preparation records while preserving original turns, selected context preset and roleplay requests. It is distinct from deleting transcript turns or application data.

Focused suites include context-core/application/reuse/refresh/delete, automatic-memory, summary-validation, response-variants, inline-images and their browser workflows. Check sequences, saved state and provider-call counts, not just final arithmetic. Important cases include fixed residual tails, historical batch boundaries, replay from originals, restart, stale/cancelled results, correction overlap, every direct consumer after unchanged repair, no-call reuse and source deletion. Synthetic coverage/equality tests do not prove real-model recall, optimal defaults or actual phone behavior.
