# ORE — Product contract

ORE (Open Roleplay Engine; repository: Roleplay Engine) is a personal roleplay application for a single owner per local installation. Predictable context handling, inspectable model input, and control over summaries take priority over feature breadth. This file records current accepted behavior and open decisions, not a roadmap or implementation diary.

Read [IMPLEMENTATION.md](IMPLEMENTATION.md) for module ownership and development, and the focused contracts linked below before changing those subsystems. The user's latest explicit decision takes precedence. Code demonstrates current behavior; it does not independently authorize a product-policy change.

## Product vocabulary

| Concept | Owns |
| --- | --- |
| Connection | Endpoint/protocol, credentials, model, physical limits, built-in and custom request parameters |
| Prompt preset | Ordered enabled text blocks and source markers, their roles and configuration |
| Context preset | Reusable memory settings and extraction, compression and repair prompts; optional summarization Connection |
| Chat | Shared title, Connection, Character/Persona, prompt and context selections, lorebook selection and working input target |
| Branch | Transcript, response variants, turn pins, Author’s note, memory and cutoff, lore activation, requests and operation state |
| Character / Persona | Separate reusable records for the model's identity / user's identity |
| Generation | Server-owned request assembly, transport, streaming and response persistence |
| Product agent | A possible future auxiliary task with instructions, a Connection, conversation access, triggers and marker output; not a coding subagent |

The accepted stack is strict TypeScript, React/Vite, Node/Fastify, SQLite with better-sqlite3/Drizzle, Zod, HTTP/SSE, Vitest and Playwright. One computer hosts server and data; other browsers access that installation. Independent testers run independent installations. No hosted service or multiplayer system is implied.

## Turns and responses

- A turn has user and assistant parts, stable identity and completion independent of text length. Only the latest turn may be pending. Resolve it before submitting another turn. Either part of a completed turn can be deliberately empty; omit blank outgoing parts without losing membership or coverage. Delete whole turns only.
- Failed, cancelled, interrupted, blank or unusable first-response output leaves its turn pending. Partial text remains inspectable but cannot be explicitly accepted as complete. Retry uses the existing pending turn; it does not add a duplicate input.
- Trim boundary blank lines from new submissions, successful responses, copied greetings and part edits, preserving internal formatting. Do not rewrite imported/existing history.
- New chats copy all nonblank resolved primary/alternate greetings into response variants of one completed opening turn with an empty user part. Select the first nonblank greeting in card order; preserve duplicates. All blank means no opening turn. Later card edits never rewrite copied greetings.
- Regenerate only the latest completed response. Keep its selected response committed until a new valid variant succeeds; failure/cancellation restores it. Selecting existing variants on historical turns changes future input, not later transcript text. Source-content provenance is distinct from monotonic concurrency revisions: A → B → unchanged A can restore memory freshness only where every dependency still matches.
- In an empty chat, **generate an opening** explicitly asks the model to write the first assistant reply. It follows the usual pending-turn and retry rules and leaves the user part empty. Regenerating the sole completed turn with a blank user part uses the same opening scene instruction and keeps previous variants. Edit **Opening scene instruction** in the selected prompt preset.
- With an empty composer, **Continue** extends the selected response of the latest completed turn, including an opening greeting or an earlier response version. The composer’s Send shortcut also activates Continue. The selected prompt preset can customize the continuation instruction. A successful continuation saves and selects a new response version with a paragraph break before the addition. The prior version remains available. The combined reply may contain up to 100,000 UTF-16 code units. Failure, cancellation and interruption keep the prior selection. Cancelling discards the unfinished continuation and its reasoning while retaining the attempt's request.
- **More → Impersonate** drafts one possible player message using the chat’s Connection. The composer supplies optional guidance that the model may rephrase. The player can type during generation or cancel it. The numbered selector browses successful suggestions. Its right arrow on the newest suggestion generates another using the current guidance. A pending version disappears from the count on cancellation or failure. Cancelling closes the panel when there is no saved suggestion and restores the latest saved version otherwise. The panel uses Story’s generation status and live reasoning preference. Its controls stay in place and are disabled when unavailable. Cancel is visible during generation. Use draft or Replace draft saves the suggestion as the shared composer draft, discards any previous draft text, and closes the panel after the save succeeds. Dismiss closes the suggestion for every device on that branch. A suggestion stays closed after reconnect or restart. Only Send commits the player’s text and starts the character’s reply. Saved suggestions stay usable after the story changes. Generating another version uses the current story context.
- Generation belongs to the server. Losing an SSE observer does not cancel work. Reconnect reconciles saved/current state. Server interruption exposes explicit recovery; it never silently repeats paid requests or claims to resume a provider stream.

## Prompt authority

The prompt preset editor opens on **Main prompt**, which lists the ordered blocks and markers. **Action instructions** contains separate disclosures for **Continue**, **Impersonate** and **Opening scene**. Both tabs share the preset draft and its Save/Cancel actions.

Impersonate has a dedicated layout. Send the character’s narrative fields, the selected persona, selected summaries when the Main prompt enables Summary, pinned turns, verbatim messages in their original roles, then the Impersonate system instruction. Pinned and verbatim messages have their own places regardless of the Main prompt’s markers. Main prompt prose, lore, Author’s notes and card instructions are excluded. The instruction supports one literal expansion of `{{draft}}`, `{{user}}` and `{{char}}`. Blank or omitted instructions use the built-in default.

Enabled preset blocks and markers compose the base request. Missing/disabled markers contribute nothing. Empty/missing-marker presets may be saved; warnings are advisory. Messages, Summary, Pinned messages and the two card instruction markers each allow at most one enabled instance. An empty resolved request fails before a provider call.

Character expands checked, nonempty Name, Description, Personality, Scenario and Example dialogue fields as separate messages in that fixed order, inheriting the marker's role. Separate field markers behave equivalently. Missing field configuration means all fields; explicit empty selection contributes nothing. Greeting is transcript content, not a Character field expansion. Selected names resolve macros even if their own field is unchecked.

Resolve case-insensitive `{{user}}` and `{{char}}` once in prompt/card/persona text, with You / Character fallback names. Insert names literally, without recursive interpretation. Stored conversation text remains literal. `{{original}}` is scoped to the two card-instruction fields and inserts only the respective marker fallback. Other macros remain literal.

Fresh installations and **Restore original** use **GLM V2.8.1-RU/RU** as the built-in prompt preset, preserving its ordered blocks, model-bound text, and Continue and Opening scene instructions. Both card markers have empty fallbacks, and Messages permits card depth injection. **New prompt** starts with an empty **Pre-history instructions** text block, the same source markers in their factory order, and an empty **Post-history instructions** text block. Existing saved presets and imports retain their blocks and permissions. Omitted depth permission means off. Card fields, lore and chat Author's notes follow [compatibility and prompt rules](docs/COMPATIBILITY.md).

### Pinned turns

Pin completed turns in Story. Membership follows the original turn and currently selected reply within that branch. Chat details opens the searchable Pinned turns manager. Open a turn from its card, or use its separate pin control. An unpinned row stays available for re-pinning until the manager closes. The input allocation keeps the last confirmed estimate while recalculating.

An enabled Pinned messages marker includes one grouped reference message in branch order, including archived turns and any pinned turns also sent through Messages. Both copies count. Missing or disabled Pinned messages produces an advisory warning for branches with pins, including while choosing a preset in Chat Settings. The marker has no effect on ordinary Messages placement, summary coverage or lore matching. See the [prompt contract](docs/COMPATIBILITY.md#pinned-messages) and [budget rules](docs/CONTEXT.md#measurement-and-limits).

### Managed and recent-history modes

With Summary enabled, Summary and Messages share one managed coverage selection: selected summaries plus the saved verbatim tail, in source order. Neither marker is inserted implicitly. Compaction saves a replacement before excluding its sources and preserves all original turns.

Without Summary, Messages uses a request-local newest contiguous suffix of whole original turns that fits complete input, including required fixed content/pending input. Archived originals are eligible. Stop at the first older turn that cannot fit; do not split parts, skip a larger recent turn, or pad slack. The saved cutoff does not restrict this mode. Required fixed content/pending input that cannot fit fails explicitly. Missing Messages inserts no turns, including pending input.

Summary-off mode performs no preparation, promotion or repair, and unused stale memory does not block roleplay. Saved summaries, selections, versions, corrections and preparation history remain intact. Re-enable Summary and use Prepare; stale required memory still needs reviewed repair. The sending tolerance does not expand recent-history suffix selection.

## Memory and budgets

Prepare measures the complete resolved input with ORE's local reference counter. Manual Prepare makes no roleplay request. Send, Regenerate, Continue and Impersonate can trigger preparation outside the sending allowance. A successful reply can trigger a separate job against the saved input target. Numerical defaults and model prompts remain tunable. Requested summary length is a soft target. Opening a chat, changing settings or sources, choosing a variant and typing a draft make no memory calls. [Measurement and limits](docs/CONTEXT.md#measurement-and-limits)

Preparation replays from original turns, reusing compatible summaries and activating each valid selection until the first fit. Summary-only prompts start with saved coverage. Regenerate excludes the previous reply and keeps its selection specific to that request. Older batches may return to verbatim or use finer summaries. The minimum tail, batch sizes and retained summary floors constrain what can fit. [Coverage and preparation](docs/CONTEXT.md#stable-coverage-and-preparation)

Changing batch or promotion size keeps committed summaries and their provenance. Review affected branches before removing obsolete memory or corrections. If preparation needs a deletion, it pauses for the dependency-cascade review. Confirm to delete and replan, or decline to stop with the memory at the pause. [Layout changes](docs/CONTEXT.md#layout-changes) and [deletion rules](docs/CONTEXT.md#deletion-and-verification-boundaries)

An edited summary stays saved even when Prepare selects different coverage. Source edits invalidate every actual consumer, including summaries that used the source as prior context. Repair visits required dependencies before dependents and retains approved progress when the review closes. Structural coverage, matching text and refusal checks cannot establish semantic recall. [Manual edits](docs/CONTEXT.md#manually-edited-summaries) and [reviewed repair](docs/CONTEXT.md#reviewed-repair)

Clear memory removes summaries, versions, candidates and preparation history. It preserves original turns, the context preset selection and roleplay requests. A branch can export its approved versions and committed selection as editable JSON, or its selected summary text in chronological order. Confirming a JSON import replaces that branch’s memory and accepts it as reviewed against the current transcript, without model calls. [Summary files](docs/CONTEXT.md#summary-json)

## Libraries and imports

Supported formats are a bounded compatibility profile, not full SillyTavern behavior: V1/V2/V3 JSON or embedded PNG character data, supported lorebook formats, persona-backup/basic JSON, ORE prompt/context JSON and SillyTavern-style solo JSONL transcript interchange. Unsupported metadata remains inactive. [COMPATIBILITY.md](docs/COMPATIBILITY.md) owns exact mappings and limits.

The Connection editor opens on **Connection settings** for provider access and token limits. **Model identifier** sits below the API base URL and key in the **Provider** section. Every streamed completion requests token usage, including for older Connections. Turn statistics show the counts the provider returns. The name, diagnostics and Save/Cancel actions are shared across both tabs. **Request parameters** provides optional controls for Temperature and Top P. **Advanced parameters** opens from a collapsed state and contains Presence penalty, Frequency penalty, Seed, Stop sequences, Reasoning effort and the JSON editor for extra provider fields. Unset values use the provider’s defaults. Extra fields are sent as top-level Chat Completions fields. The provider determines which optional parameters it supports. The JSON editor numbers logical lines and shows the first validation error. Selecting the error moves the caret to its source. Tab inserts four spaces, and **Format JSON** applies four-space indentation to any well-formed JSON object in one undoable edit. Parameter errors remain clickable at their updated positions after formatting. The JSON editor rejects built-in keys and fields that override ORE’s request structure, output limit or credentials. Field errors from **Save** and Connection diagnostics appear beside the affected control. The editor opens the relevant tab and expands **Advanced parameters** when needed. **Send test message** uses the edited parameters and displays the request.

Selecting a model for a new Connection fills **Model context window** when its endpoint reports a valid total. The field remains editable, and selecting the same model preserves a manual edit. A saved Connection remembers the reported window for its endpoint and model. On reopen, the editor shows whether the chosen window matches that report and offers a link to apply it to the draft when it differs. With no report, the editor shows that the provider limit is unknown. **Save** commits the chosen limits and the report. Model and endpoint changes clear the previous attribution. **Reserved output tokens** remains separately editable and must be smaller than the context window.

The context preset editor opens on **Memory settings**, with separate groups for turns and summary promotion. **Prompts** contains the extraction, compression and repair instructions. Both tabs share the editable preset name, summarization Connection, draft and Save/Cancel actions.

The Character editor opens on **Profile** for the portrait, speech color, description, personality, scenario, example dialogue and optional card instructions. **Greetings** holds the greeting and alternate greetings. **Lore & tags** holds the default lorebook and local tag assignments. All three tabs share the name, title/comment and character draft.

Shared reusable edits affect future requests in selecting chats and retain existing request bodies and greetings. Shared-record edits are blocked during response and memory preparation. The built-in prompt and context presets are protected from deletion and display their saved names. Fresh installations and confirmed context resets use **Эпистемика 1.5-RU**, with summarization using each chat’s Connection. Restore and Reset apply current factory values. A context layout change still requires the applicable memory impact review. App updates preserve previously saved presets.

Delete in Libraries reviews current references for Connections, Prompt presets, Context presets, Lorebooks, Characters and Personas before asking for confirmation. A linked item can be replaced with one existing item of the same type across all direct references, or cleared where its selection permits it. A Prompt clears to the built-in prompt preset. Clearing a summarization Connection makes the Context preset use each chat’s Connection. Chats that use the deleted Connection only through a preset keep their roleplay Connection. A Character’s default Lorebook changes only the defaults for future chats. Existing chat Lorebook selections are independent.

Character deletion keeps its default Lorebook unless the user opts to delete both. The joint deletion is available when no other Character or chat selects that Lorebook.

The review lists each chat once and checks all its branches. Active work and open repair reviews block the affected deletion. Context clearing requires every branch to permit it under ordinary Chat Settings rules. A Context replacement that would prune saved summaries or corrections or change committed coverage requires the existing Chat Settings review first. Deletion preserves the chats, their history, saved memory and historical request and preparation records. Search and paging control visibility. Confirmation applies to the complete reviewed set.

Owner-level bookmarks choose new-chat Connection, Prompt and Context preset defaults. Installations without saved bookmarks start with the built-in prompt and context presets bookmarked. Saved choices, including cleared bookmarks, are preserved. Clearing or deleting a choice restores the original fallback (first Connection or None, built-in Prompt, no Context preset). Deletion shows the resolved new-chat fallback for a bookmarked item and leaves the replacement unbookmarked.

Fresh installations have zero chats and open to **New chat**. **Libraries → Chats → New chat** opens the same page. The previous chat remains selected until creation succeeds, and its composer draft stays with that chat. The page shows the resolved Connection and Prompt preset, links to their libraries and offers direct Connection setup when needed. New Character and Persona actions open creation editors, and activating a selected preview opens its editor. Saving from those editors returns to **New chat** and selects the saved item. The Character Library shortcut provides access to creation and reviewed card import. The only available Character is selected automatically. A missing Connection or Character is marked on its panel. **Start chat** requires both and uses the selected Character and optional Persona. If a turn edit is unsaved, confirm before starting. A successful creation saves the character name as the chat title within the 100-character limit, copies greetings and default lore, and opens Story or Chat Settings if the saved chat needs a Connection. Saved chats open from the Chats library. Deleting the final idle chat leaves the library empty across restarts.

When saved chats exist, **All chats** beside **New chat** opens the Chats library. Desktop pairs Connection with Prompt preset above Character and Persona, with **Start chat** aligned right below. At widths up to 800 px the participants come first, followed by the Connection/Prompt pair and a full-width **Start chat**. All four panels have quiet Library shortcuts. Participant panels also offer **Create**, as does Connection when setup is required. Participant previews use Library card styling. The square Character picture fills the inner height, which the empty preview also reserves. An empty Persona panel shows optional guidance below its heading.

JSONL import previews a transcript and creates a new chat from Libraries → Chats or an independent branch from Chat branches. Confirm an editable title or branch name. Imported chats use the normal defaults, optional Character and Persona selections and the selected Character's default lorebook, then open Chat Settings. Imported branches use their chat's shared settings and open in Story. Both start with the file's turns and fresh branch state. Transcript imports skip greetings. JSONL export downloads the selected branch’s full saved transcript, including archived original messages and selected responses. See [COMPATIBILITY.md](docs/COMPATIBILITY.md#cards-personas-and-transcript-interchange) for turn mapping, format limits and information loss.

Character/Persona Title / comment and Speech color are local metadata, excluded from model text and compatible exports. Local tag assignments are independent of preserved embedded card tags. Pictures are Character-only; they do not enter model input. Organization/presentation-only saves must not invalidate narrative memory or reset lore. Duplication copies local metadata and independent picture associations, sharing reusable lorebook/tag identities as specified.

## Chat branches

Every chat has at least one branch. Chat branches opens after Inspect memory and supports name search, selection, rename, duplicate, transcript import/export and deletion. The Chats library lists each chat once, shows the turn count of the last branch opened in the current browser, and opens that same branch. If the remembered branch is unavailable, the card shows and opens an available branch. Branch selection changes the current view and uses that branch's composer draft. Deleting a branch requires confirmation and leaves the other branches usable. Delete chat removes all branches and checks every branch's saved revision.

Chat cards mark the current chat and show the latest known message time across their branches, using the same timestamp as the recent-message sort. For messages less than 24 hours old, the card shows elapsed whole hours or minutes, or **less than a minute ago**. At 24 hours or more, a message from the previous local calendar day shows **Yesterday**, and other messages show the exact local date and time. Labels update while the card is open. The tooltip always shows the exact local date and time when known. Chats with no turns show **No messages yet**. When saved turns have no known message date, the date is omitted. **Delete chat** is in the card's More menu and requires confirmation.

Duplicate copies the committed story, pins, memory, requests, current saved Author’s note and lore activation state. A fork inherits pins on the copied turns only. Membership is independent after either copy. Branch from here copies the story through the chosen completed turn and the current saved note, then opens the new branch. An earlier fork copies only memory versions whose source turns and complete dependency chain remain in the fork. Omit crossing versions, including manual corrections, without review or changes to the source branch. Start fresh lore activation for an earlier fork. Reselect compatible saved memory using the current full input budget and prefer recent original turns within the existing coverage and budget rules. If saved memory is insufficient, leave ordinary preparation available. Neither copy operation starts a model request.

## Interface and recovery behavior

Warnings use dismissible modal dialogs. An action that completes with a fallback or a choice that carries a risk opens its warning immediately. Ongoing configuration and inspection warnings remain available from review buttons, so editing and ordinary navigation can continue. Dismissing a warning keeps drafts and saved choices.

The Story turn footer keeps response versions, regeneration or cancellation, editing and pinning directly accessible when applicable. More contains reasoning, branching and whole-turn deletion. It opens with focus on the menu panel. At narrow widths the footer wraps to keep actions accessible without horizontal scrolling.

Story, the reasoning dialog and the suggestion panel follow live generation at the bottom. Scrolling up pauses following and preserves the reading position as text arrives. Scrolling back to the bottom resumes following. Story and the reasoning dialog also offer Latest turn and Latest reasoning. The suggestion panel keeps the streamed text visible until the saved suggestion loads.

When the current branch has zero turns, Story shows a first-message hint and leaves the composer in place without moving focus to it. If the chat has no Connection, the hint instead offers a shortcut to Chat settings.

**Close chat** in Chat details clears the selected chat in the current browser across reloads and opens **New chat**. It preserves composer drafts, saved branch choices and active server work. Confirm before discarding an inline turn edit. A valid chat left open can still reopen on reload.

Escape closes a click- or tap-opened popup without focusing or highlighting its opener. When the opener is available, a keyboard-opened popup returns focus to it so keyboard navigation can continue. Editable suggestions keep focus in the input for continued typing.

Escape returns from chat tools to the current Story and cancels an unsaved turn edit in Story. Open dialogs and popups handle Escape first. In Chat Settings, Escape follows Return without saving. Escape leaves in-flight saves to finish.

Chat Settings groups shared selections into Story, Generation and Context and states their scope across all branches of the chat. It shows the model for the selected Connection, prompt diagnostics beside the prompt preset, and the current branch's saved input estimate beside its editable input target. The estimate excludes composer and settings drafts. The shared Current chat sidebar shows branch counts, the saved Connection and budget, and the Context disclosure with Prompt peek.

Memory and Chat Details update Estimated input as valid steps become active. A popup floats near the top edge of the Story transcript and shows live preparation activity and Stop. It gives Load older turns space while that control is visible. Stop, failure and interruption keep the latest committed selection. Completed results that could not yet become active remain available for reuse. A pending Send turn and the previous selected reply during Regenerate remain saved. Interrupted work requires an explicit retry after restart.

Story, Libraries and Settings are top-level navigation. Chat settings, Inspect memory and Request inspector are chat tools. Prompt peek can copy the assembled model messages as plain text, with role headings in model order and selectable text when automatic copying fails. Desktop uses shared sidebars; widths up to 800px use the header's Chat details overlay and floating Save/Close controls. A click or tap on the workspace behind Chat details dismisses the overlay and consumes that interaction. Saving editors returns only after server confirmation; failures retain drafts. Library editors use Save/Cancel, with floating Save/Close at narrow widths. At widths up to 800 px, the current Library heading opens a picker that shows all seven categories and marks the current one. While the picker is open, a light backdrop dims the workspace and shields its controls from hover and press. Clicking or tapping the backdrop only closes the picker. Choosing a different category uses the same unsaved-edit confirmation as the desktop sidebar. Clicking a reusable card opens its editor; More opens secondary actions, dismissing when outside scrolling begins. Character and Persona choices, along with Connection, Prompt preset, Context preset and Lorebook choices in Chat settings, follow the sorting saved for their respective Library categories in the current browser. Optional selections keep None selected first. Shared selection dropdowns also dismiss on outside scrolling; scrolling inside options preserves them. Connection model selection uses a compact modal with automatic discovery, local filtering and manual identifier submission; discovery failure never blocks manual entry. Selection changes the editor draft until the Connection is saved. The Tags filter keeps its separate outside-scroll policy.

Application settings autosave valid changes, serialize rapid edits and reconcile only locally changed fields on conflicts. Preserve failed choices with Retry. Routine saves are silent; after one second show the pending-delay alert, and failures show immediately. App-default color pickers save immediately; library color pickers keep Apply/Cancel. Backups, deletion and reusable editors retain explicit actions/confirmations. Action-error banners offer Dismiss, while loading failures offer Retry loading. An idle foreground client detects a silent server outage. The outage warning offers Dismiss and clears automatically when the server is reachable. During the outage, Story keeps the composer editable and shows why Send is unavailable. Recovery preserves unresolved action errors. Simple delete confirmations for individual records and entries accept Enter from the heading or Delete button. Enter on the focused Cancel button dismisses the dialog.

A click or tap on a modal backdrop dismisses the top dialog through the same cancellation and operation guards as Escape. Pressing inside a dialog and dragging onto the backdrop keeps it open.

Leaving a changed Library editor or Chat settings through in-app navigation or sign-out requires confirmation. Browser document exits use the browser's native warning when available. Each tab can recover one Library draft on reload, subject to session storage availability. The editor reopens with the recovered values. If the Library revision or dataset changed, the old draft is available to copy. Newly entered API keys and unsaved picture changes require re-entry. Confirmed saves, explicit discards and successful sign-out clear the current tab's Library draft.

Each branch has one composer draft shared by devices on the same server. Autosave after a typing pause. The last save the server accepts replaces the previous draft. Keep a browser copy for recovery during a connection loss or reload. A successful Send clears the submitted draft and preserves newer saved text. Delayed saves based on state from before that Send are discarded. While Send awaits acknowledgement, the submitted text stays selectable for copying. An unanswered Send returns the draft to editing after eight seconds. Retrying the unchanged draft reuses the original command identity. If an offline edit after an uncertain Send conflicts with a confirmed send, retain the edited text for explicit draft recovery. A new or copied branch starts with an empty draft.

Typing remains available during generation/preparation while Send is blocked. The composer grows/shrinks to its height cap and keeps Send at its bottom-right. Turn editors retain manual resizing. Physical-keyboard modes are Ctrl/⌘+Enter (default), Enter, or button-only. The same setting sends from the composer and saves from either turn editor. Phone/tablet plain Return remains a newline even with an attached keyboard. Ignore composition/repeat events and never queue blocked submissions.

If the turn being edited is removed or replaced, Story keeps the unsaved text available to copy. Send and Continue stay disabled until the recovery panel is closed. The composer remains editable so recovered text can be pasted there.

In the composer and turn editors, typing `--` inserts an em dash (`—`). Typing a third hyphen immediately after that substitution restores `---` for Markdown separators. Pasted and loaded text stays literal.

Chat text scale is 90/100/110/120 percent and applies to messages, the composer and turn editors. Themes are server-wide Dark, Light, Midnight Black and Porcelain. Theme defaults yield to explicit application speech colors, then Character/Persona overrides. Speech color pickers preview the same two-message exchange as Chat appearance at the active chat text scale. Only the edited speaker's dialogue follows the picker color. The other speaker uses the application default or its theme fallback. Legacy colors remain explicit until cleared. Themes, text scale, portrait visibility and optional live reasoning preview change presentation only. Live reasoning preview defaults off; saved/on-demand reasoning inspection remains available. Show a centered title below a visible Character portrait; otherwise left-align it. Library pictures remain independent.

Markdown/direct-speech highlighting is heuristic presentation; raw HTML stays inert. Remote Markdown images render in the browser but are filtered from future model input and budgeting. Story uses a bounded transcript window without truncating engine history. iOS keeps native keyboard/selection behavior and permits contained native vertical boundary gestures in transcript/Chat details, retaining guards elsewhere. Preserve device-specific behavior without claiming emulation proves real-device support.

English and Russian ship together; language changes update mounted interface text without translating user content or changing model input. See [localization](docs/LOCALIZATION.md) and the [locked palette](docs/PALETTE.md) before changing UI text/colors.

## Data, access and delivery

The installation has one local owner login. Credentials stay on the server, excluded from ordinary responses/inspection/logs. Local SQLite keys are not application-encrypted. Backups include credentials; optional nonempty passwords protect portable files, while blank-password protection only deters generic scanners. Import/wipe preserve the accepted content/auth/preferences boundaries in [DATA.md](docs/DATA.md).

Phone access uses optional trusted-LAN HTTP, disabled initially and configured locally after owner setup. Automatic network selection/port 3000 recovers without a browser; manual mode retains its binding. Settings shows the recommended hostname and the active listener’s local IPv4 fallback together; hostname discovery failure alone leaves IPv4 access available. Local access remains independent. Keep authentication, origin/host/subnet admission and trusted-network restrictions. HTTPS provisioning is deferred; do not expose the server through public forwarding.

Windows x64 is the supported public download. Development takes place on `develop`. Only the exact commit qualified on `staging` can be promoted to `main` for publication. Published releases stay immutable. [Windows release procedure](docs/RELEASES.md#automated-windows-releases)

The external Windows launcher stays in place for routine updates. After the installed build reports readiness, the helper prepares updates for the next launch. Pausing updates also pauses activation. If launcher replacement is required, the installed build stays selected and a blocked prepared update remains available. Configuration, data and language packs survive app replacement. [Windows startup and launcher compatibility](docs/RELEASES.md#normal-windows-package-startup)

Recovery uses an explicitly selected compatible build and pauses updates. Live startup owns database identity, snapshots and migrations. A missing established database or a failure after live startup begins must never trigger empty replacement or automatic rollback. The owner's working-tree installation remains independent. [Database recovery](docs/RELEASES.md#database-upgrades-and-explicit-recovery) and [working-tree startup](docs/RELEASES.md#working-tree-development)
