# ORE — Development and architecture

Read [CONCEPTS.md](CONCEPTS.md) for accepted product behavior and [AGENTS.md](AGENTS.md) for the working agreement. Maintain current contracts when behavior changes; use Git history for old proposals and completed verification. This is not a feature diary.

## Development commands

Direct npm commands require Node 24 or Node 22.14+ within major 22 (see `package.json`); the contained launcher pins its own Node. The SQLite native binding requires Node-API 10, which Node 22.12/22.13 do not provide. Do not reuse native `node_modules` across Node majors. Install locked dependencies with `npm ci` when needed.

| Command | Purpose |
| --- | --- |
| `ORE-launcher.bat` | Windows x64 package installer/updater; built-in PowerShell 5.1, downloads a published application/runtime into adjacent `ORE-internal/` |
| `scripts/release/start-dev.bat` / `./start-dev.command` | Windows / Mac/Bash working-tree rebuild into `ore-development/`, no update check |
| `npm run dev` and `npm run dev:ui` | Two-terminal server/UI watch mode (ports 3000/5173) |
| `npm run typecheck` | Strict client/server TypeScript checks |
| `npm run build` | Typecheck and build client/server |
| `npm start` | Serve built interface and API through Fastify |
| `npm test -- tests/context-core.test.ts` | Example focused Vitest invocation |
| `npx playwright install chromium webkit` | Provision browsers, including WebKit for the Safari lorebook-scroll regression |
| `npm run test:e2e -- tests/browser/chat.spec.ts` | Example focused browser invocation; build first |
| `npm run check` | Build, Vitest and browser suites |

No lint script exists. Tests need loopback servers and temporary-file access. Use synthetic fixtures/keys and real temporary SQLite databases, mocking external provider transport. Never use active user data for destructive testing. Both start-dev entries and watch mode use repository data by default: stop the normal app before sharing that database, or explicitly set `ROLEPLAY_DATABASE` to a development path. The standalone Python lab has [its own instructions](experiments/compaction/README.md).

## Persistence and migration boundaries

SQLite lives on the server's local disk with WAL, foreign keys and short transactions. One process owns a database. Phones access HTTP APIs, never a shared database file. Store migrations resolve from module URLs, not the terminal directory. Check schema compatibility before WAL/ownership mutation for future schemas; acquire ownership and create a consistent private pre-upgrade snapshot before upgrading an existing older schema. Failed snapshot aborts the upgrade. Each migration is atomic; earlier completed migrations may remain if a later one fails. Never edit applied migrations or reset data to make an upgrade pass.

Preserve identities, source/concurrency revisions, selections, manual corrections and historical requests. SQL files plus registered data upgrades form the schema history; a missing numbered SQL file does not imply an omitted migration. `schema.ts`, Store registration, frozen legacy definitions and backup validation/reconstruction must agree. The current schema constant is in `src/shared/build-info.ts`; do not duplicate a second version authority in documentation.

Capture source/configuration/selection/operation revisions before asynchronous work. Do provider/image work outside transactions. Recheck all captured preconditions and ownership inside the committing transaction. Save summary+selection, response+variant+lore state, or compound import+receipt as coupled commits. Write failure preserves the previous valid state; later failures preserve completed progress. UI disabling is never the concurrency safeguard.

Shared library commands enforce idle/revision restrictions across affected chats. Per-chat operations preserve unrelated chats' independence. Durable command fingerprints exclude concurrency revisions where established receipts require replay; keep legacy fingerprints readable without rewriting command history. A retry must replay a committed outcome or reject altered payloads, not silently recreate a deleted record.

Library deletion has a read-only review and a separate confirmed command at `/api/library/:id/deletion`. The dependency resolver projects current selection identities, names and branch revisions without reading transcripts or credentials. The review token binds the dataset epoch, target, dependency identities and usages, bookmark fallback, and the selected action and its effects. A replacement is reviewed after selection. Store rechecks the token, library work ownership and affected branch restrictions inside the transaction. It commits shared settings, dependent library records, branch revisions, owned-resource cleanup and the exact-command receipt together, then the server publishes Library and chat notifications. The older library DELETE route still rejects live references. Current browsers opt out of the legacy Lorebook usage aggregate.

Preset layout changes preview obsolete memory across affected branches and bind the review to the saved revisions. Latest-turn deletion uses the whole-turn command and previews its memory effects. Preserve the selected prefix and its versioned provenance. Commit settings or transcript changes with the cleanup, deleted-result markers and updated cutoff in one transaction. Legacy stored layouts stay intact on load and upgrade.

Preparation holds branch ownership while waiting for deletion review. The preview token is scoped to the live run and the saved revision. Recompute the cascade and check ownership in the committing transaction. Apply the reviewed deletion and the committed and request-local cutoffs together, then replan. Cancel or restart releases the unanswered review without deleting memory.

Content imports/wipes use an exclusive gate, full-state digest and dataset epoch to prevent stale-client revision ABA. Auth/runtime authority and machine preferences remain distinct from portable content. See DATA before changing them.

Migration 16 moves shared settings to chat groups and gives each existing story a Main branch with its old ID. Turns, memory, requests and browser draft keys retain those identities. Duplicate and fork use new IDs for copied records and remap local dependencies. Model request bodies, estimates and usage stay as recorded. Forks retain independent repair source baselines for compatible memory even when the original preparation history extends beyond the fork. Revision and idle checks, copied records and the replay receipt commit in one transaction.

JSONL creation commits destination, turns, selected original variants and a digest-based receipt together. Standalone import resolves ordinary new-chat defaults at commit. Branch import addresses the parent group directly and checks its existence at commit. It uses the group's live settings and leaves sibling operations and revisions independent. Whole-chat deletion rechecks branch membership, including branches added by imports. Identical import retries return the saved branch while it exists. See [data management](docs/DATA.md) for dataset and receipt rules.

Pin membership lives on completed turn rows. The desired-state mutation checks dataset epoch at ingress and branch revision and operation ownership at commit. It advances only the branch revision. Copy remaps turn identities and keeps their membership, while whole-turn deletion removes membership with the row.

## Generation and transport

The coordinator owns one operation per branch. Existing story API IDs identify branch records. Shared settings live in the parent chat record and advance affected branches' revisions when changed. Validate/save pending input, capture settings/revisions, resolve fixed input/lore, measure full input, and prepare only under the accepted trigger. Assemble through the authoritative core path, validate limits, save a credential-free historical request, then stream the provider result. Commit only the still-owned operation. After successful response/regeneration, a separate job may prepare over-target saved input; delayed preflight cannot start after supersession, and failure cannot undo the response.

Cancellation aborts transport and rejects late results. SSE disconnection merely removes an observer. Restart marks unfinished work interrupted and offers explicit retry without model calls. Reply/reasoning checkpoints occur on incoming chunks at most once per 250 ms and on terminal outcomes/graceful shutdown; hard crash can lose later chunks. Reasoning is stored separately from turn parts and never enters narrative input, lore scanning or summary sources. Each stream has a four-million-character bound. Snapshots expose at most the final 2,000 reasoning characters; authenticated per-generation reads return full reasoning on demand.

Regeneration keeps the completed response and uses a request-local pending view with the old reply excluded from sources and dependencies. Its valid whole-summary prefix supplies the initial request estimate. Direct corrections containing the target block regeneration for explicit resolution. When preparation triggers, the same replay planner used by Manual Prepare, Send and post-reply work runs on that request-local view. The fitting selection is saved for the regeneration request. Success selects the new variant and resets and commits its lore epoch atomically. The ordinary post-reply trigger checks the branch's saved input and can reuse the generated summaries. Source-content provenance remains distinct from monotonic chat and part concurrency revisions.

Continue captures the selected variant of the latest completed turn in a generation record. Its request view supplies the target to the common assembler and budget planner while retaining the original source turns. On success, the transaction checks the branch revision and captured variant, saves and selects the combined reply, and commits the lore delta. The attempt retains only the new generation as output and the exact provider input. The browser stages the command identity in tab-local storage for explicit replay after an uncertain acknowledgement. Schema 19 adds the nullable variant reference and preserves existing generation rows and request order. Branch copies remap the reference while preserving the provider body.

`core/context-replay.ts` indexes approved results and advances one working selection through eligible saved and generated operations. Inspection uses the same planner through uninterrupted saved reuse. The coordinator owns the in-memory replay and records its estimate and the paid requests in the job. Persistence rechecks ownership, source, configuration and selection revisions before saving each result. It commits a valid branch selection and cutoff with the generated summary in the same transaction. The coordinator groups consecutive saved results into one selection update before the next wait. A selection that still needs an approved correction stays in the replay until it can include the correction. The final fit is validated independently of intermediate selection commits. Interruption keeps committed progress and all saved results. Save next summary advances and commits one replacement of the current selection.

`provider/openai.ts` implements only text Chat Completions with `model`, `messages`, `stream`, `max_tokens`, and optional usage streaming. The supported custom parameters and endpoint validation live in shared contracts. No messages/model/stream/output override is allowed. Refuse redirects; use Authorization only, never embedded endpoint credentials/query/fragment. An edited endpoint cannot receive another endpoint's saved key. Read `choices[0].delta.content`; require a coherent terminal outcome and `[DONE]`. Roleplay accepts supported `length` outcomes; summaries require a normal stop. Explicit refusal/filter, malformed/incomplete streams and blank responses fail safely. Usage is optional and remains attached to the original attempt.

Readable reasoning uses the first nonempty plain `reasoning` / `reasoning_content`, otherwise readable `reasoning_details` text/summary entries; ignore encrypted data/signatures and avoid duplicated representations. No parameters are injected to enable reasoning. `/models` discovery and the explicit `Hi` diagnostic use the Connection editor settings, the configured output reservation, and a 30-second test timeout; no independent 64-token cap, saved chat turn, automatic retry or tokenizer calibration exists.

## Reads, notifications and bounded work

`EngineSnapshot` / `Store.engineSnapshot` provide full sources/context without historical generation bodies to generation, preview, lore and memory operations. `ChatToolsSnapshot` provides full transcript/context without generation history to Memory/Setup. `StorySnapshot` and `StoryReader` provide bounded display pages; never use a display window as engine history. The full legacy snapshot remains explicit inspection only.

Story initially mounts 15 whole turns, moves in batches up to 40, and caps a window at 120. Use indexed `(chat_id, position)` queries and a short coupled read transaction, not a sliced full snapshot. Validate anchor/shift/limit/revision through the shared parser; return replacement windows and reject stale/foreign/removed cursors. Visible ordinals count surviving preceding turns. Keep global pending/generation/context status independent of the window. Pause paging during editing/focused controls, retain drafts on deletion/failure, and restore stable-identity reading anchors when prepending/trimming/resizing or leaving a tool. Latest turn is explicit; the bottom of an old page cannot authorize jumping ahead. Browser Find sees only mounted turns. Pinned turns reads a branch-wide pin projection on demand and jumps through the same revision-guarded Story anchor reader. After the page mounts, align the target without focusing the turn and close the narrow Chat details overlay. Scroll only the transcript; ancestor-wide scrolling can move the overflow-hidden document in WebKit.

Story reads the current preparation checkpoint and terminal status with branch state. Estimates come from authoritative request assembly. The Stop control addresses the generation when it owns preparation and the memory job for independent preparation. Stop uses server ownership checks even when the associated turn is outside the Story window.

Request lists use exclusive generation-identity cursors (20 descriptors by default, at most 50), plus at most one selected descriptor to retain inspection while new requests arrive. Bodies load on selection and stay immutable. Descriptors omit request prose, reasoning and partial output. Current web mutations request minimal acknowledgements and then reconcile; preserve legacy full responses.

Typed notifications distinguish chat state/stream, libraries, settings and full reconciliation. SSE comment-only keepalives (15 seconds) recheck auth without dispatching changes. The refresh queue serializes/coalesces scopes, including settlement races. Hidden/other-chat streams cause no reads; other-chat state changes update activity. Memory/Setup refresh on committed state rather than each token. Reconnect/visibility changes reconcile fully. Page reads defer notifications and recheck revisions; preserve simultaneously invalidated settings scopes.

Sidebar previews return authoritative counts/allocations without prose; full Prompt peek loads on demand and releases its body on close. Debounce idle drafts for one second; while pending, key previews to saved input rather than the next draft. Abort/guard superseded reads and never display a previous chat's result. Budget/coverage computation remains shared with actual requests. Full engine/context work still grows with saved conversation length; bounded Story rendering is not a claim of constant-time preparation or measured battery savings.

## Settings, editing and browser state

Private revisioned sidecars beside the database store LAN, appearance, new-chat defaults and chat behavior. Use strict shared schemas, private temporary files, atomic replacement, preserved malformed files and explicit recovery. These preferences survive content import/wipe but are not content backups. Language packs use installation `languages/`, independently of database overrides. Appearance versions retain legacy explicit colors; omitted old-client fields preserve current values. Read upgrade rules in the owning modules before changing schemas.

`settings-autosave.ts` and `useSettingsAutosave.tsx` serialize changes; App owns queues across navigation. Reconcile a conflict once using only submitted fields. Preserve failed/uncertain edits and read authoritative state on Retry before duplicating writes. Routine saving is silent; cancellable one-second delay alerts and immediate failure alerts use localized descriptors. Poll LAN/languages only while Settings is open; older reads cannot overwrite saves.

Composer drafts synchronously store exact text and staged command identity/revision per chat in localStorage. Ack clears only submitted content, preserving later edits. Definite rejections permit a fresh explicit command; uncertain outcomes retain identity across reload for safe retry. Storage failures retain memory text and prompt copy-before-leaving. Dataset changes require explicit recovered-draft reconciliation. Never persist repair candidates under the composer recovery policy.

Author's notes use branch settings JSON with empty/system/depth-0 defaults and branch revision and idle guards, and no backfill for old records. Their autosave queue keeps explicit pending field changes (including reverts after uncertain writes) in epoch/branch browser keys. Requests time out after 15 seconds, retain edits, and expose Retry even outside the popup. Send/retry/regenerate wait for note reconciliation. Closing the popup retains accepted saves; chat switches cannot apply stale responses elsewhere. Notes are ordinary backed-up chat content, excluded from summary inputs. See compatibility for placement.

Command failures offer Dismiss and loading failures offer Retry loading. Connection warnings have independent dismissal and recovery state. Reconnection reconciles saved data without clearing an unresolved action error or retrying a write. Failed editors retain user input; only accepted discard workflows delete drafts.

`LibraryDraft.tsx` owns the Library leave confirmation and installs `beforeunload` while an editor is dirty. A versioned `sessionStorage` draft captures the editor, its starting dataset epoch and Library revision, and the serializable form values. Flush pending storage writes when the page becomes hidden, on `beforeunload`, and when the editor unmounts after losing authentication. Restore after authentication and current Library load. Keep stale recovery copyable and preserve the server's existing Library revision and epoch checks. Drafts stay independent across tabs and devices. Sign-out clears the initiating tab only after acknowledgement. A sibling signed out through the shared session can recover its own draft after authentication. Draft recovery never replays a write.

Top-level views and Library editor selection currently use React state. When adding in-app browser history entries, guard same-document Back and Forward transitions that would leave an unsaved editor with the same confirmation used for in-app navigation. Declining keeps the draft and leaves the visible view and history position in sync. Confirming reaches the requested history entry once. Verify both outcomes in both directions. Keep the native `beforeunload` warning for document exits.

`WarningDialog.tsx` uses the shared native modal and confirmation layout. Use `WarningDialog` for a warning raised by an action or interruption, and `WarningDetails` or `WarningMessages` for advisory details the user can reopen while the condition persists. Keep field validation, operation progress and failed-command recovery at their controls. Format localized warning descriptors at render time.

Shared controls preserve accessible labels, keyboard focus, 44px touch targets and existing hover roles. Search fields use the Library search pattern with a magnifying glass, a localized placeholder and an accessible name. The Connection model picker fetches on opening with current endpoint/key settings; closing or superseding it aborts its browser request and ignores late results. The modal fits the visual viewport, keeping search and actions in flow around a separately scrolling, incrementally rendered model list. Dialogs initially focus their heading or container. Use the shared modal lifecycle to restore focus on close and handle Escape for pointer-opened popups. Turn actions retain their selector, with disabled pending placeholders and live cancellation. Inline reasoning preview is passive and preference-gated; on-demand reasoning follows the selected attempt and rejects stale fetches. Library metadata timestamps update transactionally at real changes, not stream checkpoints/reads/retries; unknown legacy dates stay unknown. Sorting is browser-local, deterministic and does not mutate snapshots or prompt state.

## LAN admission

Keep local loopback available separately from the optional listener. `lan-policy.ts` admits eligible private RFC1918 IPv4 interfaces with contiguous /8–/30 masks, excludes tunnel/virtual adapters, and validates the actual socket address, exact hostname/IP+port and current-subnet peer. Forwarded headers never confer trust. The LAN listener cannot create the owner or change LAN settings, including from the server computer. Session/origin/content-type/CSP checks remain active; HTTP has no Secure cookies or transport encryption.

Automatic mode persists enabled intent and recovers offline/busy port 3000 without browser interaction, preferring the existing adapter then stable interface order. Manual mode prepares a replacement listener before the atomic settings commit and preserves the old binding on failure. A serialized queue owns save/recovery/shutdown; recheck interface identity/address/netmask per request and on a three-second monitor. Disable revokes authority and closes LAN sockets before acknowledgement but does not cancel accepted work. Shutdown rejects late bind results and releases timers/sockets.

macOS uses bounded Bonjour LocalHostName discovery; other platforms depend on existing OS hostname resolution. Live status derives both URLs from the committed listener binding and port, with an explicit hostname availability state. Known discovery/normalization failures allow IPv4 startup with a localized hostname notice; unexpected errors remain failures. Only the validated, present hostname and the selected IPv4 are admitted. The compatibility `runtime.url` prefers hostname when available and otherwise uses IPv4; these URLs require no saved-settings upgrade. No DNS service, router rule or certificate installer is provided. Treat hostname/device/suspension coverage as platform qualification, not a consequence of browser emulation.

## Contained delivery boundaries

The repository root exposes `ORE-launcher.bat` for Windows package delivery and `start-dev.command` for Mac working-tree startup. `scripts/release/` owns the contained builders, installed start/recovery entries and Windows development startup. Working-tree builds use allowlisted local files and exact Release builds export the same input set from Git. Installed source builds start directly from their selected private runtime and app. [Legacy recovery](docs/RELEASES.md#legacy-installations) covers retired delivery paths.

`portable-launch.mjs` verifies assets/runtime, owns the foreground application process, presents approved messages and catches browser spawn/exit failures. `application-start.mjs` is the installed application's startup boundary: it resolves established database identity, checks compatibility, invokes the server and records database readiness. Store retains SQLite ownership, missing-file enforcement, snapshots and migrations. Retained older applications without that boundary keep explicit compatible recovery guards. Server readiness and ownership/port failures use structured IPC; console matching cannot establish readiness. Saved-data startup never participates in update fallback.

`generate-windows-launcher.mjs` emits the protocol-2 external batch and BOM-marked installed PowerShell helper from separate entry bodies and shared primitives. The ASCII batch prefix reads its UTF-8 payload from its own path passed as environment data. Established startup checks the managed home, ACL and helper compatibility before invoking the helper in the same PowerShell process. First activation and the compatibility update for helpers predating bounded release comparisons run in a separately owned worker so its lease and job end before handoff. The installed helper owns routine update policy and the server lifetime. Keep the external bytes stable across routine package releases. The lookup, invocation and descriptor contract live in [delivery](docs/RELEASES.md#external-windows-launcher-contract).

Windows downloads a release descriptor, archive and checksum from one resolved public GitHub Release. The descriptor binds the full commit, platform/architecture, package protocol, archive byte count and SHA-256. Validation precedes execution; extraction validates the complete ZIP listing for Windows aliases/collisions, types, traversal and bounds. Installation replaces only versioned application/runtime/recovery payloads and launch tooling, retaining `.env`, data, identity metadata and language packs. A foreground OS file lease covers update and server lifetime; named kill-on-close Job Objects stop owned descendants after controller loss. The next owner checks the recorded prior job for quiescence before changing installation state, so lease release alone cannot authorize overlapping work while prior workers are still stopping. New package updates do not create directory locks that can survive interruption. Legacy state is reconciled only when its owner cannot still be active; see [delivery](docs/RELEASES.md).

`windows-qualify.yml` runs only for `staging` pushes or explicit staging dispatch. It checks the exact candidate SHA, runs `npm run check` on Windows x64, builds a contained Release installation with `-ReleaseBranch staging`, and verifies packaging and package-installer acceptance before retaining immutable artifacts for 30 days. `develop` has no automatic workflow. `windows-release.yml` on `main` performs publication only: `ci-promote-windows.mjs` requires a successful staging qualification for that exact SHA, validates the workflow/repository/event and unexpired artifact identity, downloads by immutable artifact/run IDs with digest mismatch treated as an error, rechecks qualification and archive/launcher identity, then calls the existing draft publisher. There is no fallback build or full test run on main. Push promotion must preserve main ancestry; squash/merge commits without their own staging qualification fail. Only publication receives release-write permission. The release contains `ORE-launcher.bat`, `ORE-windows-x64.zip`, its checksum and `ORE-windows-x64.json`, tagged `build-FULL_COMMIT`. Previously published releases are not rewritten and an older publication cannot displace a newer Latest. See [delivery and promotion commands](docs/RELEASES.md).

`scripts/release/build-portable.ps1` serves CI and developers. Release mode requires clean exact Git sources. Development mode builds current local edits. `scripts/release/start-dev.bat` enables local-only dependency reuse through `development-dependencies.mjs`: package/runtime-keyed caches, junctions to read-only dependency files and staged dependency inventory verification. Those snapshots retain build tools and cannot be packaged; ordinary portable builds retain fresh locked installs and production pruning. Private Node invokes npm directly; `build-windows.mjs` bundles the interface and emits server JavaScript without repeated type analysis because full developer validation runs before distribution. Notices, native/startup checks, selections and application-owned database boundaries remain authoritative and are described in [delivery](docs/RELEASES.md).
